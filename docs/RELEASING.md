# Как выпустить новую версию

Для разработчика (Claude). Пользователю ничего делать не нужно: он получит сообщение в боте и нажмёт «Обновить».

1. Работа идёт в ветке `main`. Перед выпуском — все проверки:
   `bash tests/run_all.sh --fresh` (локально) и зелёный GitHub Actions.
2. Поднять номер версии в двух местах — они должны совпадать (это проверяет тест):
   - файл `VERSION` в корне;
   - `VERSION = "…"` в `core/app/release.py`.
3. В начало `core/CHANGELOG.md` добавить раздел `## X.Y — ДД.ММ.ГГГГ` и 3–8 пунктов «- …» простыми словами.
   Эти пункты бот покажет владельцу (предложение обновиться) и всей семье (после обновления).
4. Если нужны разовые действия на сервере (Caddy, новые строки в `.env`), обновление по кнопке их не сделает —
   выпустить такую версию отдельной инструкцией для Claude Code, а в CHANGELOG не обещать работающего до этих шагов.
5. Закоммитить в `main` и выпустить:
   ```
   git push origin main
   git push origin main:stable
   ```
   Через 30 минут или меньше агент на сервере увидит новую версию, владелец получит сообщение.
6. Обновить сайт — можно в той же версии: историю (`LOG`) и дорожную карту (`LANES`) править в `site-src/data.js`, номер версии — `VERSION` в `site-src/build.py`, затем пересобрать:
   `python3 site-src/build.py core/app/static/site --repo` (готовые страницы коммитятся).

Миграции базы только добавляют (новые таблицы, колонки с значениями по умолчанию): при откате кода
старая версия должна работать с новой базой.

Откат вручную на сервере: `cd /opt/assistant && git log --oneline -5`, затем
`git checkout --force <коммит> && bash scripts/update.sh` — только с согласия владельца.
