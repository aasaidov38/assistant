# Демо-кабинет на сайте (версия 1.10.7): установка через Claude Code

Демо — это отдельный адрес `https://demo.assistant.saidov.ru/`, где любой посетитель нажимает одну кнопку и попадает в настоящую
панель ассистента с вымышленной семьёй Ветровых (Алексей, Мария и двое детей, история за полгода). Можно добавлять траты, писать
в чат, отмечать лекарства, смотреть гараж и поездки. Правки видны только самому посетителю и исчезают через 20 минут без действий
(или через час от начала), либо сразу по кнопке «Начать заново».

Что гарантирует безопасность:
- Демо — **отдельные контейнеры** (`demo` и `demo-db`) со своей базой. Реальных данных вашей семьи там нет, и добраться до них
  из демо нельзя: у демо нет ни `.env`, ни токена Telegram, ни ключей TickTick и Алисы.
- Для каждого посетителя на лету создаётся личная копия вымышленной базы и удаляется после сеанса.
- ИИ в демо настоящий, но по **отдельному ключу с лимитом расходов**: 10 сообщений на сеанс, 300 обращений в сутки на всё демо.
  Фото, голос и загрузка выписок отключены.
- Одновременно не больше 8 посетителей, не больше 10 новых сеансов в час с одного адреса. Остальные видят «все места заняты».
- Из интернета открыты только стартовая страница, `/demo/*` и `/web/*`. Всё остальное (API ядра, документация) закрыто.
- Страницы демо не индексируются поисковиками (`robots.txt`, `noindex`).

Нагрузка на сервер: контейнеры `demo` (до 300 МБ) и `demo-db` (до 256 МБ). Основной ассистент от них не зависит: если демо
упадёт или займёт всю свою память, бот и панель продолжат работать.

Что нужно заранее:
- вход на сервер по SSH-ключу работает: `ssh assistant "hostname"`;
- на сервере уже установлена версия 1.10.7 или новее (ставится кнопкой «🔄 Обновить» в боте; сам по себе этот шаг демо не включает);
- доступ к DNS домена `saidov.ru` (там, где вы управляете записями);
- кабинет провайдера ИИ, чтобы выпустить **второй ключ** с лимитом.

---

## Часть 1. Что сделать самому (мышкой, 5 минут)

1. **Запись в DNS.** Откройте управление DNS домена `saidov.ru` и добавьте запись:
   - Тип: `A`
   - Имя (хост): `demo.assistant`
   - Значение: `95.81.74.236`
   - TTL: по умолчанию.
   Если у `assistant.saidov.ru` настроена запись `AAAA`, добавьте такую же и для демо; если нет — не нужно.
2. **Отдельный ключ ИИ.** В кабинете провайдера, через которого работает ассистент (GPTunnel или другой), создайте **новый** API-ключ
   только для демо и поставьте ему лимит расходов (хватит 300–500 ₽ в месяц). Основной ключ не используйте: если демо
   кто-то «выжмет», рабочий ассистент не пострадает. Ключ скопируйте, он понадобится ниже.

Расход ИИ в демо ограничен трижды: 10 сообщений на сеанс, 300 обращений в сутки и лимит на самом ключе.

## Часть 2. Задание для Claude Code

Откройте Claude Code в любой папке и вставьте задание целиком. Ключ ИИ Claude у вас не спросит и не увидит: его вы вставите сами
через `nano` на шаге 3.

```
Задача: включить на сервере демо-кабинет моего семейного ассистента (версия 1.10.7) по адресу demo.assistant.saidov.ru.

Сервер: ssh-алиас `assistant` (root, Ubuntu 24.04). Ассистент лежит в /opt/assistant (Docker Compose), рядом работают
n8n в /opt/n8n, Caddy в /opt/caddy (там же Caddyfile). Версия 1.10.7 уже установлена (git-ветка stable). Подробности: docs/DEMO_CLAUDE_CODE.md в репозитории.

Правила:
- Не выводи на экран содержимое /opt/assistant/.env и любые ключи, токены, пароли. Проверять можно только наличие строк
  через grep -c.
- Ключ ИИ для демо я вставлю сам через nano. Ты его не запрашиваешь и не вписываешь.
- Перед изменениями делай копии. Ничего не удаляй.
- Перед каждой командой, которая что-то меняет, коротко скажи, что она делает.
- Если шаг завершился ошибкой — остановись, покажи вывод (без секретов) и предложи, что делать.

Шаги:
1. Проверь сервер и память. Для демо нужно ещё около 600 МБ:
   ssh assistant "cd /opt/assistant && cat VERSION; free -h; swapon --show; df -h / | tail -1;
     docker compose ps --format '{{.Name}} {{.Status}}'; dig +short demo.assistant.saidov.ru"
   Ожидается VERSION 1.10.7 или новее. Если свободной памяти (available + swap) меньше 700 МБ — остановись и сообщи.
   Если dig ничего не вернул, запись DNS ещё не появилась: скажи мне, продолжать можно, но HTTPS-сертификат Caddy получит
   только когда запись заработает.

2. Копии перед изменениями:
   ssh assistant "set -e; D=\$(date +%F_%H%M); cp /opt/assistant/.env /root/assistant.env.bak-\$D;
     cp /opt/caddy/Caddyfile /root/Caddyfile.bak-\$D; ls -l /root/*.bak-\$D"

3. Попроси меня вписать ключ вручную. Покажи мне команду и жди ответа «готово»:
     ssh -t assistant "nano /opt/assistant/.env"
   В конец файла нужно добавить две строки (я их впишу сам):
     COMPOSE_PROFILES=demo
     DEMO_LLM_API_KEY=ключ-для-демо
   Сохранить: Ctrl+O, Enter, выйти: Ctrl+X. Если строка COMPOSE_PROFILES уже есть, добавить `demo` через запятую.
   После моего «готово» проверь только наличие: ssh assistant "grep -c '^COMPOSE_PROFILES=.*demo' /opt/assistant/.env;
     grep -c '^DEMO_LLM_API_KEY=.' /opt/assistant/.env" — ожидается 1 и 1.

4. Запусти демо:
   ssh assistant "cd /opt/assistant && docker compose up -d --build demo-db demo"
   Подожди до 2 минут и проверь:
   ssh assistant "cd /opt/assistant && docker compose ps --format '{{.Name}} {{.Status}}' | grep demo;
     docker compose logs --tail 40 demo | grep -E 'ДЕМО|Заготовка демо|Traceback|Error'"
   Ожидается «Ядро … запущено в режиме ДЕМО» и «Заготовка демо … собрана», без Traceback.

5. Добавь адрес в Caddy (/opt/caddy/Caddyfile). Проверь, нет ли блока: ssh assistant "grep -c 'demo.assistant.saidov.ru' /opt/caddy/Caddyfile"
   (если 1 и больше — пропусти). Иначе допиши в конец файла:

demo.assistant.saidov.ru {
	@demo path / /robots.txt /demo /demo/* /web /web/*
	handle @demo {
		request_body {
			max_size 256KB
		}
		reverse_proxy assistant-demo:8000
	}
	respond 404
}

   Затем:
   ssh assistant "cd /opt/caddy && docker compose exec -T caddy caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile &&
     docker compose exec -T caddy caddy reload --config /etc/caddy/Caddyfile --adapter caddyfile"
   Если validate ругается — верни копию Caddyfile из /root/Caddyfile.bak-… и сообщи мне.

6. Проверки снаружи (пока DNS не обновился, пропусти и скажи мне):
   - curl -s -o /dev/null -w '%{http_code}\n' https://demo.assistant.saidov.ru/            → 200
   - curl -s -o /dev/null -w '%{http_code}\n' https://demo.assistant.saidov.ru/docs        → 404
   - curl -s -o /dev/null -w '%{http_code}\n' https://demo.assistant.saidov.ru/v1/inbound  → 404
   - curl -s -o /dev/null -w '%{http_code}\n' https://demo.assistant.saidov.ru/web/api/me  → 401 (без демо-сеанса)
   - curl -s https://demo.assistant.saidov.ru/robots.txt                                    → Disallow: /
   - основной сайт не пострадал: curl -s -o /dev/null -w '%{http_code}\n' https://assistant.saidov.ru/ → 200
   - полный проход: создать сеанс и проверить данные:
       curl -s -c /tmp/demo.jar -o /dev/null -w '%{http_code}\n' -X POST https://demo.assistant.saidov.ru/demo/start   → 303
       curl -s -b /tmp/demo.jar -H 'X-Requested-With: panel' https://demo.assistant.saidov.ru/web/api/me | head -c 300
     В ответе должно быть "name":"Алексей" и "demo":true.
       curl -s -b /tmp/demo.jar -X POST -H 'X-Requested-With: panel' https://demo.assistant.saidov.ru/demo/reset -o /dev/null -w '%{http_code}\n'  → 303
     (потом rm /tmp/demo.jar)

7. Проверь, что основной ассистент не пострадал: ssh assistant "cd /opt/assistant && bash scripts/check.sh"
   и напиши мне в Telegram боту любое сообщение (я проверю сам).

8. Итог: коротко напиши, что включено, сколько памяти осталось (free -h) и что мне сделать вручную, если что-то не прошло.
```

## Часть 3. После установки

- Откройте `https://demo.assistant.saidov.ru/`, нажмите «Открыть демо» и пройдите по разделам. Внизу в чате напишите
  «Пятёрочка 1450 продукты»: запись появится в «Финансах». Кнопка «Начать заново» сразу сбрасывает все ваши правки.
- На сайте проекта кнопка «Попробовать демо» ведёт на этот адрес.

### Как это работает (кратко)
- При запуске демо собирает **заготовку**: пустую базу + миграции + вымышленные данные. Раз в сутки заготовка пересобирается, чтобы
  «сегодняшние» записи, сроки платежей и документов не уезжали в прошлое.
- Кнопка «Открыть демо» создаёт для посетителя копию заготовки командой `CREATE DATABASE … TEMPLATE …` (занимает доли секунды) и ставит cookie.
  Каждый запрос панели идёт в базу своего посетителя. Через 20 минут без действий база удаляется.
- Ссылку на демо можно присылать в мессенджеры: предпросмотр ссылки сеанс не создаёт (создаёт только нажатие кнопки).

### Настройки демо (необязательно)
Добавляются в `/opt/assistant/.env` (через `nano`), затем `cd /opt/assistant && docker compose up -d demo`:

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `DEMO_MAX_SESSIONS` | 8 | Сколько посетителей одновременно |
| `DEMO_AI_DAILY` | 300 | Обращений к ИИ в сутки на всё демо |
| `DEMO_SITE_URL` | `https://assistant.saidov.ru` | Куда ведёт «Хочу такой же» |
| `DEMO_DB_PASSWORD` | как `POSTGRES_PASSWORD` | Пароль базы демо |

Остальные пределы (10 сообщений ИИ на сеанс, 20 минут простоя, 60 минут на сеанс) заданы в `core/app/config.py`.

### Выключить демо
В `.env` убрать `demo` из `COMPOSE_PROFILES` (или удалить строку), затем:
`cd /opt/assistant && docker compose stop demo demo-db && docker compose rm -f demo demo-db`.
Блок `demo.assistant.saidov.ru` в Caddyfile можно оставить или удалить. Данные демо одноразовые, терять там нечего.

### Если что-то не работает
- «Демо готовится» на стартовой странице: заготовка ещё собирается (первые 10–30 секунд после запуска или обновления). Подождите минуту.
- «Все места заняты»: открыто 8 демо; освободятся через 20 минут простоя. Можно поднять `DEMO_MAX_SESSIONS`, если хватает памяти.
- В логах: `docker compose logs --tail 100 demo` (никаких секретов там нет).
- ИИ в чате отвечает «ИИ в демо выключен»: не задан `DEMO_LLM_API_KEY`, либо ключ не подошёл.
- Курсы валют и погода в демо живые, берутся из интернета; если у сервера нет выхода в сеть, эти карточки могут быть пустыми. На остальное это не влияет.
